# স্বাধীন শিক্ষক রিভিউ ও আসল অ্যাকাউন্টে গ্রহণযোগ্যতা যাচাই

এই checklist প্রস্তুত করা হয়েছে; পূরণ করা হয়নি। মালিকের প্রকাশ-অনুমোদনকে শিক্ষক বা সরকারি syllabus certification বলা যাবে না। বর্তমান প্রকাশ ও কারিগরি প্রমাণ `production-release-receipt.json`-এ আছে।

## বিষয়শিক্ষকের জন্য

Offline reader `questions.html`-এ chapter/type/search filter ও উত্তর দেখার ব্যবস্থা আছে। প্রতিটি `chapter-N.html`-এ সংশ্লিষ্ট অধ্যায়ের ৩২০টি প্রশ্ন আছে। Canonical records: `content/question-bank/ssc/biology/chapter-N/`; source/provenance ও author review সংশ্লিষ্ট ফাইলে।

প্রতি অধ্যায়ে পরীক্ষা করতে হবে:

- ২০০ MCQ: stem-এর স্বচ্ছতা, একটিমাত্র সঠিক উত্তর, distractor-এর গ্রহণযোগ্যতা, answer/explanation-এর মিল।
- ৫০ CQ: স্বয়ংসম্পূর্ণ উদ্দীপক, ক/খ/গ/ঘ-এ ১/২/৩/৪ নম্বর, সংশ্লিষ্ট জ্ঞান/অনুধাবন/প্রয়োগ/উচ্চতর দক্ষতার গভীরতা ও যুক্তিসম্মত sample solution।
- ৭০ SQ: প্রয়োজনীয় সংজ্ঞা/তুলনা/কারণ/উদাহরণ, যথেষ্ট কিন্তু অপ্রাসঙ্গিক নয় এমন উত্তর।
- বর্তমান সরকারি বইয়ের edition ও page/figure মিল; কোন অংশ enrichment তা আলাদা নথিভুক্ত করা। কোনো web background-কে official page proof হিসেবে গণ্য নয়।
- একই অর্থের পুনরাবৃত্তি ও cross-type conceptual overlap; lexical screen পাসকে semantic review ধরা যাবে না।
- চিত্রের label, stimulus-সংশ্লিষ্টতা, বাংলা লিখিত বিকল্প এবং mobile/print পাঠযোগ্যতা।
- Board/school/year provenance না থাকলে এমন attribution না যোগ করা।

## জীববিজ্ঞানের পরীক্ষার কাঠামো

সরকারি নম্বর/সময় blueprint এখনও নিবন্ধিত নয়। শিক্ষককে category, নির্বাচিত syllabus/topics, প্রতিটি section-এর প্রশ্নের ধরন, offered/answer count, নম্বর, total ও সময় দিতে হবে। অনুপস্থিত কাঠামো অনুমান করে সরকারি বলে দেখানো যাবে না।

## আসল শিক্ষক অ্যাকাউন্টে browser checklist

Production-এ নতুন test account/role/payment/quota তৈরি বা বদলানো হয়নি। পরীক্ষক নিজের বৈধ অ্যাকাউন্ট ও অনুমতিতে নিচের কাজ করবেন; password, cookie বা OTP রিপোর্টে লিখবেন না।

1. Desktop ও mobile থেকে নিজের অ্যাকাউন্টে লগইন; SSC বিজ্ঞান → জীববিজ্ঞান নির্বাচন।
2. Chapter বাছাই, MCQ/CQ/SQ ও উত্তর-ব্যাখ্যা/চিত্র দেখা। ভুল হলে question ID ও ব্যক্তিগত তথ্যবিহীন screenshot নথিভুক্ত।
3. Auto Model-এ শিক্ষক-নির্ধারিত marking scheme দিয়ে পূর্ণ বই বনাম অল্প অধ্যায় পরীক্ষা। পূর্ণ স্টক থাকা বইয়ে selected-topic ঘাটতি হলে ঘাটতির বার্তা চাই; AI generation নয়, অন্য অধ্যায় দিয়ে পূরণ নয়।
4. Model preview, settings পরিবর্তন, reload ও existing saved draft অক্ষুণ্ণ আছে কি না পরীক্ষা।
5. Print preview-এ ক/খ/গ/ঘ, নম্বর, চিত্র ও বাংলা font পাঠযোগ্য কি না দেখুন।
6. Payment/checkout আলাদা acceptance test: এই কাজের automated checks দিয়ে বাস্তব অর্থ লেনদেন বা paid provider E2E পাস দাবি করা হয়নি। অনিচ্ছাকৃত charge নয়।

নথি: পরীক্ষকের অনুমোদিত পরিচয়/ভূমিকা, browser/device, source/deployment, পদক্ষেপ, প্রত্যাশিত/প্রাপ্ত ফল, question ID এবং অনুমোদিত evidence। সফল না হলে certification flags false-ই থাকবে।

## Database backup blocker

Source archive database recovery backup নয়। বিদ্যমান manual `site-data-backup.yml` workflow একটি read-only Neon logical dump ও source encrypt করে; plaintext production dump কখনো Git/Drive-এ দেবেন না। প্রয়োজনীয় `DATABASE_URL` ও কমপক্ষে ২০-byte `BLOB_BACKUP_PASSPHRASE` GitHub Actions-এর repository secret হিসেবে নিরাপদে সেট থাকতে হবে। Secret value chat বা issue-তে দেওয়া যাবে না। Encryption key-এর আলাদা নিরাপদ recovery custody দরকার।

Preflight কেবল fixed issue code দেখায়, secret value নয়। Preflight পাস হলেও dump, encrypted roundtrip ও artifact সফল হওয়ার আগে backup সম্পন্ন নয়। `pg_restore --list` এবং encrypted roundtrip বাস্তব restore rehearsal-এর বিকল্প নয়; production-এ restore নয়।
